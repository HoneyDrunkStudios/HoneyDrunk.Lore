# What's new in Azure Container Apps at Ignite'26

[Azure Container Apps](https://aka.ms/aca) (ACA) is a fully managed serverless container platform that enables developers to design and deploy microservices and modern apps without requiring container expertise or needing infrastructure management. With built-in autoscaling (including scale to zero), per-second billing, advanced networking, and built-in observability, ACA lets teams focus on their code instead of their clusters. [Since Build’26](https://techcommunity.microsoft.com/blog/appsonazureblog/whats-new-in-azure-container-apps-at-build26/4524184) we have continued to innovate on two fronts: [Azure Container Apps Sandboxes](https://sandboxes.azure.com/docs/sandboxes/), which provide secure, isolated environments where agents can run untrusted code, and the infrastructure behind Microsoft’s agent platforms that customers can use to build their own agent platform, and [Azure Container Apps Express](https://learn.microsoft.com/en-us/azure/container-apps/express-overview), the fastest way to deploy a container image as an internet-reachable app, with no environment to provision. Both are now generally available, and this blog covers everything we are announcing at Ignite’26.

## Azure Container Apps Sandboxes are now generally available

Introduced in [preview at Build’26](https://techcommunity.microsoft.com/blog/appsonazureblog/introducing-azure-container-apps-sandboxes-secure-infrastructure-for-agentic-wor/4524131), ACA Sandboxes are [now generally available](https://techcommunity.microsoft.com/blog/appsonazureblog/azure-container-apps-sandboxes-now-generally-available/4559125). Sandboxes are a first-class resource type alongside apps, jobs, and dynamic sessions, enabling you to build your own agent platform with your choice of framework, lifecycle services, and governance, designed with zero-trust security provisions. Each sandbox is an isolated microVM that boots from cached images in under a second, can be suspended with its full memory and disk state snapshotted, and resumes in under a second. Stopped sandboxes incur no compute charges, and a single sandbox group can burst to thousands of concurrent sandboxes.

The GA release includes lifecycle controls, snapshots, an egress proxy with host allowlists, deny policies and credential injection, virtual network integration, persistent volumes, and telemetry export, along with the Python and TypeScript SDKs, the aca CLI, Bicep, and a [preview Terraform provider](https://github.com/Azure/terraform-provider-aca).

Sandboxes are quickly becoming the Azure standard for customers to build agent platforms and multi-tenant SaaS. The same infrastructure already runs cloud sandboxes in [GitHub Copilot](https://docs.github.com/copilot/concepts/about-github-sandbox), [Foundry Hosted Agents](https://techcommunity.microsoft.com/blog/appsonazureblog/running-foundry-agent-service-on-azure-container-apps/4518598), [Azure SRE Agent](https://learn.microsoft.com/en-us/azure/sre-agent/security-overview), and Azure Container Apps Express. The pattern is simple: govern the agent in Microsoft Foundry, and let its work run in a disposable sandbox with scoped identity and network access. To get started, see the [Sandboxes overview](https://learn.microsoft.com/en-us/azure/container-apps/sandboxes-overview).

## Azure Container Apps Express is now generally available

ACA Express, which we introduced in [preview in May](https://techcommunity.microsoft.com/blog/appsonazureblog/introducing-azure-container-apps-express/4519150), is [now generally available](https://techcommunity.microsoft.com/blog/appsonazureblog/azure-container-apps-express-is-now-generally-available/4559101). You bring a container image, and Express handles the rest: no environment to provision, no networking to configure, and no scaling rules to write. Apps are running in seconds, start from zero in well under a second, scale to and from zero automatically, and are billed per second. Express runs on Azure Container Apps Sandboxes and is available in more than 40 Azure regions.

ACA Express is gaining momentum since launch, with customers creating Express apps across thousands of Azure subscriptions, growing at >35% MoM. Alongside this new adoption, we’re automatically moving eligible existing apps to Express, so more customers can benefit without needing to manage the transition themselves. These migrations are designed to improve performance while preserving the features and capabilities those apps already use.

Express is getting closer to feature parity with Consumption, and the rest of the features are coming soon. Express is purpose-built for developers who want to ship fast (SaaS apps, APIs, web dashboards, and prototypes) and for agents that deploy on demand (MCP servers, tool-use endpoints, and human-in-the-loop UIs). To learn more, see the [Express overview](https://learn.microsoft.com/en-us/azure/container-apps/express-overview).

## Introducing built-in interactive integration of Azure SRE Agent in Azure Container Apps

ACA has built-in integration with [Azure SRE Agent](https://sre.azure.com/). The Container Apps portal now has a first-class experience for interactive debugging with SRE Agent, [launched in preview](https://aka.ms/aca/sreagent). Developers can start a session from any container app and get evidence-backed, actionable root cause analysis and expert answers in minutes, with nothing to deploy. Each session is serverless and on demand. It starts in seconds, stays focused on your question, and ends when you’re done. ACA is the first Azure service to bring this experience to customers, and we plan to extend it to more services in the future.

Getting started takes a click. Select Debug with Azure SRE Agent on any app and ask your question in your own words, for example “*Why did my latest revision fail to start?*” or “*Why is my app scaling out so often?*” The agent already knows which app you are looking at, asks for your approval before it reads anything, and then works through your app’s configuration, revisions, deployment history, Azure Monitor metrics, and Log Analytics logs, much like an experienced SRE would. It runs read-only with your own Azure identity, so it never changes your resources and only proposes fixes, and each session runs in an isolated sandbox that is deleted when the session ends. When an issue needs more help, the agent can draft a support request for you to review and submit to Azure Support, or you can deploy Azure SRE Agent right from the session to bring that intelligence to your entire environment.

## Azure Container Apps is now a target in Azure Migrate

We are announcing that Azure Container Apps is now [available as a target in Azure Migrate](https://techcommunity.microsoft.com/blog/appsonazureblog/introducing-azure-container-apps-as-a-target-workload-in-azure-migrate/4571669). Azure Migrate can discover and assess Java web apps running on Apache Tomcat and .NET web apps running on .NET Core, and help you plan the move to ACA with a wave plan. The migration then continues in GitHub Copilot app modernization, which handles code changes, containerization, and deployment. Together they give teams a single path from discovery to a running container app. See [Migrate to Azure Container Apps with Azure Migrate](https://learn.microsoft.com/en-us/azure/container-apps/migrate-azure-migrate) to learn more.

## Additional Enhancements and Ecosystem Updates

**More regions**: Since Build’26 we have continued to expand ACA’s global footprint, adding six new regions: Germany North, New Zealand North, Chile Central, Korea South, Belgium Central, and Jio India Central. Express is available in more than 40 Azure regions.

**New tooling in VS Code**: Azure Container Apps Sandboxes are [now integrated directly into Visual Studio Code](https://techcommunity.microsoft.com/blog/appsonazureblog/introducing-azure-container-apps-sandboxes-in-visual-studio-code/4573296), making it easier to create and manage secure, isolated environments without leaving your development workflow. Developers can execute commands, create snapshots, and manage sandbox lifecycle directly from the ACA extension.

**Bring your own orchestrator to ACA Jobs**: ACA Jobs are a great fit for batch processing, ETL, machine learning, and other tasks that run to completion, but many teams already have an orchestrator. The new [Bring Your Own Orchestrator collection](https://techcommunity.microsoft.com/blog/AppsonAzureBlog/bring-your-own-orchestrator-to-azure-container-apps-jobs/4541275) provides 13 community-maintained templates for connecting the workflow engine you already use, such as Airflow, Temporal, Argo Workflows, Dagster, Prefect, Durable Functions, and Logic Apps Standard, to ACA Jobs. You keep your control plane, and ACA Jobs runs the work on serverless, scale-to-zero infrastructure.
