# Introducing Projects

Source: [Introducing Projects](https://cursor.com/blog/projects)

## Attributed content summary

Cursor describes Projects as persistent coordination for work spanning multiple sessions, such as migrations, feature development, and recurring maintenance. A coordinator delegates implementation while remaining available for direction.

Projects run on cloud machines and can dispatch local agents when machine-specific testing is needed. Synchronized files carry research, artifacts, codebase knowledge, and workflow preferences across agents. Subscriptions can trigger work from schedules, pull requests, or communication channels.

The engineering patterns include investigating a feature before parallel implementation, applying an agreed migration approach incrementally, and converting repeated design-system mistakes into lint rules. These mechanisms connect durable context with event-driven execution and feedback.

The announcement describes a beta rollout. Productivity and delegation-scale figures are vendor observations; the article does not establish equivalent gains, safety, or resource costs for HoneyDrunk. Treat persistent coordination and reusable context as patterns to evaluate, with review and validation appropriate to the work.
